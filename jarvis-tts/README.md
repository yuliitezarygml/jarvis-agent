# Русский голос Jarvis на своём сервере

Сервис синтезирует новые русские фразы на CPU по выбранному пользователем образцу. Fish Audio использован только для получения исходной записи; при работе сервиса его API и ключ не нужны. Локальная модель не воспроизводит движок Fish S2.1 Pro: сходство тембра оценивается отдельно пользователем.

## Текущее развёртывание

- Ubuntu LXC: `192.168.50.38`, API: `http://192.168.50.38:8080`.
- Каталог `/opt/jarvis-tts`, Python 3.12 в `venv`, пользователь и systemd-сервис `jarvis-tts`.
- Модель [ArtShtorm/Shtorm-PocketTTS-RU](https://huggingface.co/ArtShtorm/Shtorm-PocketTTS-RU), вариант `fast`, ревизия `33f6c328d62c4da5c1227bbe081e89b574a6183a`. Условия использования весов см. в карточке модели.
- PyTorch CPU; четыре потока, один процесс Uvicorn. Точные установленные зависимости сохранены в `requirements.lock.txt`.
- Поддерживается только русский язык. Приложение сейчас работает в русской версии; румынский голос удалён.

Выбранный оригинал: Fish `s2.1-pro-free`, reference ID `680d74fbef69419f87cfc70f092a1451`, 665294 байта, фактическая длительность 13,86 с. SHA-256:

```text
f51dfc56e3ceb35e69b4caf5cd64595312ad29590af00ea6d703bd41d77d40ac
```

На сервере исходник сохранён в `refs/original-fish-ru.wav` и `refs/user-confirmed-original.wav`; активный `refs/jarvis-ru.wav` — его копия. Исходники и уже выданные пробы не перезаписывать. Эта запись имеет потоковую длину-заглушку в WAV-заголовке: длительность считать по фактическим аудиобайтам.

## Обслуживание

```bash
systemctl status jarvis-tts --no-pager
journalctl -u jarvis-tts -n 40 --no-pager
/opt/jarvis-tts/venv/bin/python -c 'import urllib.request; print(urllib.request.urlopen("http://192.168.50.38:8080/api/health").read().decode())'
systemctl restart jarvis-tts
```

Сервис включён для автоматического старта. В unit закреплены адрес LAN, непривилегированный пользователь, доступ на запись только в кэш и лимит памяти 6 ГБ. API предназначен для доверенной локальной сети; аутентификации и публичного размещения эта реализация не добавляет.

Для обновления скопировать `server.py`, `prepare_model.py` и при необходимости unit в соответствующие каталоги сервера. При изменении unit выполнить `systemctl daemon-reload`; затем перезапустить сервис и дождаться `ok: true` в `/api/health`. Не менять образец одновременно с обновлением кода: состояние голоса загружается при старте.

## Подготовка нового окружения

Нужны Linux x86_64, Python 3.12, `uv`, отдельные системный пользователь и каталог `/opt/jarvis-tts`. Не устанавливать зависимости в системный Python или непосредственно на хост Proxmox. Команды ниже предполагают, что каталог, пользователь, файлы сервиса и WAV уже подготовлены:

```bash
uv venv --python 3.12 /opt/jarvis-tts/venv
uv pip install --python /opt/jarvis-tts/venv/bin/python \
  --index-url https://download.pytorch.org/whl/cpu 'torch==2.15.0+cpu'
uv pip install --python /opt/jarvis-tts/venv/bin/python \
  -r /opt/jarvis-tts/requirements.lock.txt
install -d -o jarvis-tts -g jarvis-tts -m 700 /opt/jarvis-tts/cache
```

До включения автономного режима выполнить подготовку с доступом в интернет от имени пользователя сервиса. Здесь загружаются веса и вспомогательные модели; ключ Fish не требуется:

```bash
cd /opt/jarvis-tts
runuser -u jarvis-tts -- env \
  JARVIS_TTS_HOME=/opt/jarvis-tts \
  HF_HOME=/opt/jarvis-tts/cache/huggingface \
  HF_HUB_DISABLE_XET=1 HF_HUB_DISABLE_TELEMETRY=1 \
  /opt/jarvis-tts/venv/bin/python prepare_model.py
runuser -u jarvis-tts -- env \
  JARVIS_TTS_HOME=/opt/jarvis-tts \
  HF_HOME=/opt/jarvis-tts/cache/huggingface \
  HF_HUB_DISABLE_XET=1 HF_HUB_DISABLE_TELEMETRY=1 \
  /opt/jarvis-tts/venv/bin/python -c 'from server import Engine; Engine().load()'
install -m 644 jarvis-tts.service /etc/systemd/system/jarvis-tts.service
systemctl daemon-reload
systemctl enable --now jarvis-tts
```

`prepare_model.py` закрепляет конфигурацию, веса и токенизатор на одной ревизии и создаёт `cache/model-config.yaml` с локальными путями. Прогрев загружает также Silero Stress и RUNorm. Unit включает `HF_HUB_OFFLINE=1` и `TRANSFORMERS_OFFLINE=1`: перезапуск должен проходить с уже заполненным кэшем. При переносе установки сохранять кэш и повторно создавать конфигурацию, если абсолютный путь изменился. Для другого IP изменить `ExecStart` в unit.

## API и подключение приложения

`GET /api/health` сообщает готовность, модель, поддерживаемые языки и `external_tts: false`.

```bash
curl --fail http://192.168.50.38:8080/api/tts \
  -H 'Content-Type: application/json' \
  -d '{"text":"Сэр, я готов к работе.","lang":"ru","format":"mp3","speed":1}' \
  --output jarvis-test.mp3
```

Поля запроса: `text` (1–2000 символов, слова или числа), `lang: "ru"`, `format: "wav" | "mp3"`, `speed` от 0,6 до 1,6. Отдельные `25`, `3.14`, `Windows` или `CPU` допустимы: RUNorm нормализует их для того же русского голоса, наличие кириллицы в каждом фрагменте не требуется. Полностью пустой/символьный текст отклоняется. Максимум 90 секунд сгенерированного аудио. Один запрос синтезируется за раз, ожидание слота ограничено 10 секундами; повторные фразы берутся из кэша на 32 записи. Ответ содержит `X-Synthesis-Ms` и `X-Voice-Cache`. Обрыв запроса отменяет генерацию; декодер завершается до допуска следующего синтеза.

Профиль приложения уже настроен для проверки: `voiceMode: "server"`, `ttsServerUrl: "http://192.168.50.38:8080"`, русский голос `fish:ru`, скорость 1, эффекты выключены. `fish:ru` — внутренний идентификатор маршрута: в режиме `server` он обращается к указанному серверу, не к Fish Audio. Ключи и профиль пользователя в Git не добавляются.

Кэш коротких ответов приложения учитывает адрес сервера, режим, голос и скорость. При переключении сервера старые аудиофайлы другого голоса не подставляются. При недоступности сервера приложение показывает ошибку и текст ответа; автоматического переключения на другой голос нет, в том числе для коротких подтверждений имени.

RUNorm совместим с токенизаторами без необязательного `token_type_ids`: локальный обработчик `normalize_anglicisms` сохраняет транслитерацию английских слов в русских фразах и удаляет поле только при его наличии. Пакет в `site-packages` не изменяется; не убирать этот обработчик при переустановке. Исходная ошибка приводила к HTTP 500 для фраз с Jarvis, Windows и CPU.

## Проверено и ограничения

- 8 тестов API, включая наличие/отсутствие `token_type_ids` и фрагменты без кириллицы: `cd /opt/jarvis-tts && venv/bin/python -m unittest -v test_server.py`.
- Живые запросы: русский текст и числа, WAV/MP3, скорость, попадание в кэш, неверные параметры, обрыв и следующий запрос. Автономный перезапуск сервиса прошёл.
- Приложение: 113 тестов, проверка типов и сборка. Живой сервер после исправления: русская фраза с Jarvis/Windows/CPU и числом 25 — около 4 с; короткий ответ MP3 — 1,8 с, подтверждение — 0,66 с, повтор из кэша — 0,11 с. Отдельные 25/Windows/CPU/3.14 — примерно 0,6–1,4 с. Это отдельные замеры без времени воспроизведения.
- На CPU синтез новой короткой фразы занимал примерно 1,4–3,9 с; это отдельные замеры, не гарантия полной задержки ответа ИИ. В стартовой проверке приложения русская фраза вместе с воспроизведением заняла около 5,9 с.

Приложение пока получает целый аудиофрагмент перед воспроизведением. Настоящий ранний старт потокового аудио остаётся в плане. Сходство с оригиналом Fish, живой микрофон, акустическое эхо и перебивание на реальном устройстве требуют пользовательской проверки. XTTS-пробы в отдельном окружении не используются основным сервисом.
